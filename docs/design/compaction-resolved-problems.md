This closes only the original engine inventory leaf at `core/context-compaction.ts:579–580`, the semantic phrase test on the model's generated resolved-problems reply. It does not migrate the separate conversation/tool candidate-selection decisions and does not close THE13.

The four existing extraction prompts and summary-generation calls are unchanged. No reply (provider generation failure or whitespace-only response) retains the existing generation fallback without making a semantic negative claim. Once a nonempty reply exists, its section cannot be assembled until a reading settles.

`engine.compaction.resolved-problems` is registered with the runtime compaction fidelity/retention decisions. It asks whether the complete reply reports at least one actually resolved problem. Quoted words such as “no resolved problems” do not decide the answer. Mixed resolved/open work counts as reporting resolved work; proposals and hypotheses do not. This is a reply reading, not independent verification that the reported fix is true. The existing retention/fidelity quality gate still evaluates the completed handoff against the source conversation.

- Settled yes: include the entire generated reply verbatim.
- Settled no: omit this section.
- Confirmation-range or uncertain reading: throw an explicit unresolved error. No default human broker is installed.
- Missing port, unavailable transport, malformed answers, unsafe input, oversized evidence or cancellation: propagate an operational failure. No keyword/regex fallback and no fabricated “none” result.

The yes/no reading uses the shared medium-stakes band. The synthetic cases exercise behavior and infrastructure, not semantic accuracy of a live model. ## Evidence and ownership

The complete reply passes the engine's local protected-input snapshot before looking up the port. The shared `gate/judgment-text.ts` helper inspects raw syntax, identifies complete embedded JSON object/array spans, rejects duplicate members before whole-object parsing, and applies the canonical structured snapshot to preserve method/key/value, form-control and nested-card relationships. It also decodes JSON string tokens to expose escaped keys and nested encoded strings. All checks reuse the existing declared-field/PAN/auth/structured controls, bound total work and do not change the reply. Ambiguous duplicate-member JSON fails explicitly, even for otherwise harmless fields; it is never silently reduced to its last member. The named reader repeats that protection for direct and calibration callers. Shared request-budget validation refuses oversized evidence without clipping. The shared wire-answer validator checks the answer type and finite unit probability before `readYesNo` is consumed. Evidence and generated text are never reconstructed from the answer.

The installed canonical engine error/judgment port owns transport, outage retries, runtime shutdown and decision-log disposal. This leaf creates no retry loop, timeout owner or broker. Compaction captures the installed port/model binding before generation; replacement, removal, late installation and model changes invalidate the operation. The same captured binding is checked before shared retry attempts, after readings and before conversation replacement, so an older compaction cannot borrow a newer composition. `QualityScoreOptions.beforeAttempt` is an additive optional field that forwards the same binding to retention and fidelity, including their shared retries; it adds no retry owner. `CompactionContext.signal` is an additive optional field carrying the existing caller lifetime through structured extraction, the new reply reading, distiller extraction and the existing quality scorer. Abort checks after asynchronous steps and immediately before replacement prevent a late result from committing after cancellation.

`ConversationManager.compact` uses its already-existing message revision to fence replacement. Append, streaming update, branch replacement and change-then-restore invalidate the original compaction. The generic `compactConversation` host boundary also snapshots and compares exact message data, rejects a stale supplied context, and never records lineage for a failed replacement. A host returning fresh arrays remains valid. This adds a commit fence, not another conversation/lifecycle owner.
