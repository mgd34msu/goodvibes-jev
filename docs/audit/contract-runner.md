# Contract runner: the post-part audit (R.13)

This is the audit that closes the contract runner (ledger task R, parts R.1 to R.13). Every file in `packages/engine/sdk/src/platform/contract/` and `contract/batteries/` was read, with `runtime/contract-composition.ts`, the `goodvibes-contract` bin and the parts of the orchestration engine the runner drives (`orchestration/phase-runner.ts`). Every place code decides something was read for what it actually decides, and its disposition was chosen on that (owner ruling 2026-09-27): a decision about what text means or whether work is good is a Jev reading; a fact of structure or of the machine (a field present, an id format, a cycle, a file existing, an exit code, a count, a status move, a format the code itself dictates) is code. The live proof (`bun run --cwd packages/engine contract-proof`) found further defects, listed with the audit's.

Paths are under `packages/engine/sdk/src/platform/` unless they start with `packages/` or `docs/`.

## Observed outside the runner

- **Free models first when benchmarks are unknown.** The route planner orders a tier's candidates by benchmark, then price. The benchmark leaderboard names models differently from provider catalogs, and the planner reads only identities already known, so on a machine with OpenRouter configured nearly every candidate has no benchmark and the standard tier's shortlist is its free models. The proof's first runs routed the planner to free models that returned no plan. The runner now gives the planner benchmark facts (item 22), but matching leaderboard names to catalog ids is the routing subsystem's (E.4) and is reported to its owner. The proof names the providers it runs on (`CONTRACT_PROOF_PROVIDER_KEYS`).
- **A provider refusing for billing.** With the machine's Anthropic key, every request was refused ("credit balance is too low"); the runner failed the contract with that message, as it should. This is an account limit, not a defect.
- **Two stall routes were seen live.** A unit whose only open item was a quality reading stalled after three checks without progress and went to the owner; with the gate results in the quality state (item 16) that loop no longer arises from a claim the gate shows.
