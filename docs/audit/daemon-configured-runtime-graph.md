The daemon then passes its runner, operator, hooks and fleet controls to the existing consumers. It does not build a second legacy workstream engine. Resource ownership begins immediately after each constructor returns. The all-required poller registration replaces only explicitly provisional ownership entries, avoiding double disposal while preserving ordinary equal-label owners. The outer scope drains handler surfaces before the distributed runtime and base graph. Callers must await `close()` before releasing paths or transferring ownership; the legacy `dispose()` wrapper starts that same observed cleanup.

Independent review of the first checkpoint found that its interval-only fixture missed a delayed default-workspace index writer and borrowed-config callbacks. The default `ProjectIndex` is now owned immediately: disposal clears its timeout and flushes accepted entries, and later mutations or a suspended reroot cannot reopen a disposed index. The stale timeout callback also checks retirement before writing. Feature-settings and optimizer unsubscribe handles are registered alongside an ownership-aware config hook release. Hook attachment keeps its exclusive last-attachment-wins behavior; each attachment has a distinct generation, so an old release cannot detach a newer attachment of the same object or revive an older runtime. The borrowed config remains usable. Real-graph regressions cover the review reproductions and failed startup followed by reuse of the same config; all observed config subscriptions are released.

The review also found that the graph did not own its `ProcessManager`. It now closes admission and immediately begins terminating owned children while accepted credential-name readings settle concurrently. Those readings currently have no caller cancellation seam, so close still waits for them; the post-read admission check prevents a late spawn. Owned POSIX jobs run in fresh process groups, and their same-group descendants are cleaned when the leader exits before the job reports done. The manager does not retain a bare group ID for an arbitrarily later close. TERM/KILL escalation uses finite timer bounds and reports failure if exit cannot be verified. Existing `kill_on_timeout: false` lifetimes remain external by default; `kill_on_close` makes ownership explicit. External jobs retain output/exit observation for their owner, and their pipes are not forcibly closed. Windows direct handles and descendants deliberately escaping a process group remain explicit limits. Synthetic process and real-composition tests cover these boundaries without signalling unrelated processes.

The checkpoint manager adds `drain()` for an owner that has stopped new calls. It waits for accepted initialization and serialized Git work, removes subscriptions that late initialization created, and waits through queued follow-on work. An unused manager is not initialized by cleanup. Individual operation errors remain observable to their callers. Four real temporary-workspace regressions cover unused shutdown, paused initialization and late subscription removal, and both successful and failing writes; the cross-process lock is absent when drain completes.

The original fixture now uses the real product runtime and server on loopback. The configured boot test exercises inbox HTTP reads, draft and payment gateway reads, session contract snapshots and complete awaited shutdown. A failed inbox constructor is followed by successful reuse of the same owned root, with no observed intervals left after either shutdown. Provider metadata and inbox adapters are explicit test fixtures. These checks make no live inference, mail, payment, SSH or cloud calls.
