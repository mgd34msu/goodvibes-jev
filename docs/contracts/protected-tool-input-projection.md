# Owned tool-input projection prerequisite

This THE-123 increment moves explicitly registered input projections ahead of
ordinary tool readers and observers. It does not enable the existing Agent
research-report consumers, screen arbitrary prose, or qualify a live local
service. Those adoption/framing requirements and THE-35 remain open.

## Registration and immutable input

`ToolRegistry.register` accepts a trusted, out-of-band `inputProjection` owner.
It is not tool-definition JSON or a flag accepted from model arguments. An
omitted registration option preserves ordinary tools; an explicitly unavailable
required projector holds the protected tool. The registry captures the complete
input through descriptor-only checks and the existing protected-input floor
before invoking the projector. Original declared credential/card refusals are
not converted into redactable permission.

`projectCall` produces a frozen registry-owned call bound to the exact call ID,
tool, executor, schema and registration incarnation. Its projected argument
identity can be reused by `prepareCall` without resampling the projector.
Copied arguments, a forged handle, or a serialized marker cannot create that
binding. Cancellation, authority and registration checks fence asynchronous
projection and retry boundaries. A hold or operational failure never returns
the original arguments or an empty successful payload.

Ordinary repair, JSON Schema validation, permission admission and the private
prepared-call/one-use claim remain separate. Projection cannot grant execution.
The projector either refuses repaired changes or validates its protected
bindings while allowing ordinary unrelated repairs. The final executor receives
the exact admitted arguments; original values are not restored into those
arguments after admission. The synchronous post-claim tail has no new host
callbacks. Resource cleanup is awaited, including unused and held captures.
Noncooperative projectors must finish/drain before their owner reports cleanup;
the registry does not abandon a late operation behind a cancellation race.

## Initial ingress and offered revisions

The actual foreground tool-response path captures/projects the batch before
pending-tool publication, conversation insertion and contract reporting. The
provider's incremental tool-call fragments are withheld from stream events:
index-only fragments do not yet identify a complete registered tool or input.
Ordinary text streaming continues, and the completed owned call supplies tool
arguments later. Outer arrays and call wrappers use descriptor-only data reads,
without borrowed map/species/iterator methods or inherited getters. The
delegated runner applies its existing execution defaults first, then projects
before conversation insertion, argument summaries, history and ordinary
permission readers. A failed batch releases its partial captures without
publishing an earlier successful prefix. Unknown tools retain their existing
recoverable failure path after local input preflight.

`prepareCall` also enforces the registered projector before repair. The direct
registry execution route enforces it before its own repair/body path. Old
duck-typed embeddings without the new owner, raw calls to a tool body, the
separate phased executor and model/provider text outside these argument paths
are not certified by this prerequisite.

An offered autonomous revision is input even if it is never selected. The
permission manager therefore owns an opaque projection of the complete host
catalog before initial admission. Every original alternative still faces the
unchanged privacy floor. The original authority/source/catalog fingerprint
remains private and current; only projected alternatives become semantic
evidence. Continuation revisions bind the original host reference, projected
arguments, schema and projector incarnation. IDs, ordering and resume-condition
meaning remain intact. Selection restores only the matching manager-owned
projected argument identity, then performs fresh preparation and admission.

All live callbacks run before the final callback-free snapshot checks, so a
later alternative cannot revoke an earlier alternative unnoticed. A changed
source, catalog, configuration, registration or projection holds the logical
call. Existing consumed-revision limits, deferral rules and one-use execution
remain in force. Unselected resources are released with the whole logical call.

## Independently framed research references

`createFramedResearchReferenceProjector` is a bounded functional adapter over the
existing protected local source owner. Its closed framing protocol is an ordered
`references` array of complete `{ id: 'S1', url: originalUrl }` cells, with IDs
matching their positions. This protocol is supplied by the registered consumer;
it does not discover URL ranges in free text. Every complete original and every
decoded parameter name is preflighted before the first role request.

The existing registered Jev battery receives only decoded query names. The
proposal model is never invoked. A preserved reference becomes a stable source
label in generic tool input. A credential-role or malformed reference becomes an
explicit omission in the same array position. Both ordinary and sensitive URL
values, hosts, paths and fragments remain out of generic repair/admission input.
No URL is reconstructed, stripped of a query, or replaced with another resource.

The original reference remains behind its source owner's immutable handle. An
empty frozen execution-context capability and the exact prepared-argument
identity allow the tool body to call `resolveFramedResearchReference` for the
same source ID. A registry-owned execution lease also binds that context and
exact argument object to the final combined execution signal. Later preparation
or execution cancellation retires access while a body is still running; body
settlement retires its lease before resource drainage. A callback-free final
lease check follows source-authority callbacks. Shared empty context tokens
cannot overwrite or retire another exact argument object's lease.
Missing/foreign contexts and copied arguments fail. A preserved
reference resolves to the exact original bytes; an omitted reference never
resolves to its original. Release, cancellation and source-authority revocation
retire access. This is reference access, not an admission, safe-URL predicate,
retrieval permission, publication approval or complete content-privacy reading.

Other argument fields are not privacy-cleared by this adapter. In particular,
URL echoes in prose, unbound/control-split references and full report fields need
the remaining value-safe framing design. The existing research editor and
public report tools are not silently switched to this limited protocol. Their
future adopter must preserve source positions/claim bindings, await editor
capture, and handle edits, repeated Submit, Close and workspace replacement.
It must reconcile the source owner's bounds with report limits without clipping
the original or releasing a partially screened report.

All verification uses synthetic data, intercepted bodies and owned local
fixtures. No live calibration, private source transfer, release or deployment
is implied.
