# Protected research report consumer adoption

THE-123's Agent report consumers use the existing protected local source owner.
This is consumer wiring with synthetic verification, **not** selection or
qualification of a live screening deployment. THE-35's service identity,
no-forwarding/no-retention and semantic calibration evidence remains open.

## Explicit composition and held default

`composeAgentToolRegistry` accepts the trusted `researchSourceOwner` capability.
The composition root must establish the requirements in
[protected-source-screening](protected-source-screening.md); no URL, environment
variable, model argument, string flag or loopback address creates that authority.
This change does not discover a service, create credentials or select a default
provider. Without the capability, report writes and report-editor submissions
hold before ordinary readers or persistence. Other research/workspace actions
keep their existing paths. The UI explains the missing trusted owner.

The registry binding is process-local and does not serialize into tool schemas,
settings, history or report metadata. Its owner still belongs to the trusted
host, including final owner shutdown. Individual submissions release their own
handles and await cleanup, without closing another submission's owner.

## Complete original and immutable preparation

All original report data faces descriptor-only capture and the existing
protected-input floor before source parsing, trimming or display bounds. Proxies
and accessors are refused. Every string value and object key participates in
full-source screening; keys must remain unchanged. Routing/control identities
cannot be redacted into a different action. The source owner generates and
verifies exact spans; the consumer does not infer URL continuations from
whitespace, join prose, classify credential parameter names itself, or ask a
hosted model to redact originals.

Original reports are limited to 40,000 UTF-16 units including keys and at most
50 source rows. The worst-case original/candidate source batches plus complete
reference handles must fit the owner's 128-handle bound. Batches contain at most
eight exact strings. Oversized reports, invalid source slots, capacity holds or
any unavailable/uncertain batch withhold the whole report. No first-50 clipping,
empty successful fallback or partially released prefix is used. The artifact's
existing 80,000-character final formatting limit remains separate.

Each independently declared URL cell also uses the existing name-only Jev
query-role battery. That battery sees names only. Credential-role or malformed
references are omitted completely, including scheme/ASCII-host-case aliases in
all report fields. Originals remain full screening evidence. Literal omission
is applied to deterministic candidates before those candidates are screened,
so a partially redacted URL echo cannot escape by failing an original-URL match.
Only candidate projections are released. An ordinary declared reference changed
by privacy screening holds rather than becoming a different usable citation.
Preserved references retain the original query bytes, duplicate parameters,
percent encoding and fragment.

Source rows retain their original order and count, including rows with omitted
URLs. Empty/invalid array slots hold; they are never filtered into reassigned
S1/S2 citation positions. Changed LF record count or pipe-cell framing holds.
Ordinary multiline prose remains intact unless genuine verified spans select
sensitive material. The previously pending control-split prompt and report
controls now run through actual asynchronous source screening with synthetic
span proposals and Jev readings.

## Registered ingress and direct consumers

Registered `agent_research_report`, all `research` report aliases,
`agent_harness` report workspace actions, and the public `workspace` report
aliases project before generic repair, admission, progress and conversation
readers. Route selection reuses each consumer's deterministic selector, including
workspace action ID/label/search resolution. Agent's late-registration safety
wrapper forwards registration options; it must not discard required protection.

The exact cleared argument binding may be used by the report body and its fixed
adapter projections. Repaired changes hold. Direct report factory calls also
prepare before artifact-store invocation; copying a plain object does not itself
mint a screening receipt. Confirmation and normal effect permission still apply.

This consumer differs deliberately from the earlier role-only framed adapter:
that adapter hides *all* original URL values from generic readers because it has
no complete privacy receipt. This consumer releases fully privacy-screened text,
including an unchanged URL only after both receipt scopes settle. A name-role
receipt alone never permits this release. Neither receipt grants retrieval,
publication, external transmission or tool execution authority.

## Editor and persistence lifetime

The real workspace captures all raw field values before asynchronous work.
Repeated Submit is coalesced. Edit, navigation to another field, Cancel, Close,
reopen, editor replacement or context/dispatcher replacement invalidates the
pending attempt. Cancellation releases source handles, stops local requests and
awaits cleanup. Currentness is checked around waits and immediately before the
synchronous prompt commit. A stale completion neither submits a prompt nor
restores an old editor/status. The generic synchronous prompt formatter cannot
submit an unprepared report.

Artifact persistence is invoked only after complete settled/current preparation.
The existing artifact-store interface has no revocable write transaction: once
`create` has been invoked, later cancellation cannot promise rollback or erase
already-released content. Tests and UI must not claim that stronger guarantee.

## Proof boundary

Tests use owned literal-loopback proposal/System One fixtures and synthetic
content. They exercise actual report artifacts, registered tool projection,
public report/workspace aliases, the actual workspace controller, exact citation
identity, all text fields, partial-alias redaction, uncertainty, limits,
revocation/cancellation and awaited cleanup. Scripted readings establish
containment and integration behavior, not model accuracy or live deployment.
No real private content, service credentials, publication or release is involved.
