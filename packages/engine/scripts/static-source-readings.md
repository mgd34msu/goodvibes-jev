# Static source observations

`internal-id:check` and `todo:check` validate recorded Jev observations offline.
Neither command contacts a provider. Confirmed violations fail validation.
Missing, stale, malformed or unsettled evidence is reported as an inconclusive
advisory. It remains unknown in the receipt; source review determines whether
work is needed. Advisories do not block releases or weaken the required functional,
type, API, build and startup checks.

The internal identity rule offers complete identifiers, literals, comment units
and prose to read for repository-development coordination labels. Syntax-only
punctuation has no textual candidate payload. Product users' tasks, workstreams
and display labels remain domain data. Versions, protocol tags, key names and
literal fixtures also remain evidence data. Historical decision records keep
their existing exemption. The source checker's own implementation, documentation
and fixtures are excluded by the exact paths in `internal-identifier-rule.ts`;
their descriptions of prohibited labels are necessary to implement the check.
This exclusion does not apply to other scripts or tests.

The unfinished-work rule uses TypeScript syntax to offer complete comment
blocks, direct return strings, error-message strings and runtime strings containing
the existing uppercase marker tokens. Those tokens identify candidates.
They do not decide whether work is unfinished. Actual inline judgment-fixture
literal data keeps its narrow syntax-based exemption. Comments and executable
fixture callbacks remain candidates.
The reading distinguishes unfinished required repository behavior from runtime
user drafts, completed late binding, repaired historical defects and declared
synthetic scoring fixtures. A required missing implementation remains a lead
even when the comment defers it to a future round.

Prepare observations explicitly with the configured genuine System One port:

```sh
bun packages/engine/scripts/read-static-source.ts \
  --log .tmp/static-source.sqlite \
  --inputs .tmp/static-source-inputs.json \
  --checkpoint .tmp/static-source-checkpoint.json
bun run internal-id:check
bun run todo:check
```

Commit `packages/engine/etc/static-source-readings.json.gz` with the source it
describes. The local input capture and SQLite log retain the complete request
inputs and genuine provider evidence for review. Source preparation is suitable
for approved public source or synthetic fixtures. Do not submit private source
or credentials without their existing authorization.

The canonical receipt uses deterministic, lossless gzip with an epoch timestamp.
Decompress it to inspect the complete current evidence JSON, including original
raw answers and capture manifests. The reader validates the same complete schema and evidence;
invalid compressed data produces inconclusive advisories. Custom paths ending in `.gz` use gzip;
other custom paths keep plain JSON.

Each observation binds the exact path, complete source hash, offered anchors,
context, decision source, site, version, question, requested model and observed
pinned model. Raw probabilities retain their original precision. A source
change invalidates its prior observations. A decision-source change invalidates
the artifact until explicit revalidation or new reading.

An unsettled group can be revised through smaller exact candidate subsets.
Every subset retains the original context and every candidate remains covered.
A subset that stays unsettled remains an advisory. This process has a finite
candidate tree and never substitutes a token-based verdict.
Reading plan version 3 gives an unsettled single candidate one exact-identity
selector request using the named weak-anchor choice and fit questions. Weak-anchor
version 2 reads actual offered text and decoded literals in complete source
context; generated ids and coordinates only locate the candidate. It retains the
original presence answer. Complete settled no fits for every offered candidate
clear weak presence even when routing confidence remains unsettled. A settled
positive candidate identity contradicting those no fits remains held. A positive selection needs both a settled
choice and a settled yes fit. Uncertain fits, unresolved positive selections and
semantic contradictions remain held. A settled yes presence cannot be cleared by a
contradictory negative selection. Each new selector capture binds its named
battery and original source manifest; older captures cannot supply this new
measurement. Once answered, a held selector is retained without resampling.
Unchanged original plan-2 answers can be explicitly revalidated under plan 3;
their original capture plan, question, time, identity and probabilities remain
intact, with the current validation plan recorded separately.
Source windows retain their complete original numbered lines. Markdown also
retains actual preambles, ATX heading ancestry, table headers and fence boundaries.
Parsed TypeScript and JavaScript structured-data declarations retain their complete
binding or expression, attached comments, module preamble and imports when the
window cuts that declaration. These are untrusted source evidence; a declaration's
name or a claimed fixture role grants no exemption and makes no local decision.
Already complete declarations keep the original context unchanged.
Before dispatch, complete source windows must fit both actual canonical presence
and selector budgets. An oversized group splits into smaller windows; a complete
unit that cannot fit fails without clipping or submitting partial evidence.

The generator retains current observations, including held answers. It does not
resample an unchanged held input on an incremental pass. A retained observation
can be revalidated after an extractor change only when its complete request,
questions, site, version, pinned model and canonical reading policy still match.
Its original capture hash, time, identifier and raw answers remain intact; the
artifact records the current validation hash separately. Changed comment units
require new genuine calls. Original source manifests and prior captures retain
the provenance of reused observations.
The canonical receipt contains exact current input keys and their complete active
subset trees. All referenced source manifests, original capture identities and raw
answers remain intact, including held observations. The separate local checkpoint,
journal and SQLite log retain prior observations and capture lineage losslessly.
Gates use only the exact current input key and independently validate its source
and policy; historical entries cannot authorize current code.

Progress is saved separately. The canonical artifact is published atomically
only if the source snapshot is still current. If source changes during a run,
rerun the command to retain matching observations and read changed inputs again.
Each answered call also reaches the fsynced append-only checkpoint journal with
its complete input and original evidence. After interruption, the generator
resumes missing selectors or exact subsets without repeating admitted answers.
An incomplete root remains held. Torn journal records remain inert audit bytes.
`--inventory-only` lists the input counts without contacting the provider.
`--all` requests a new capture of every input and retains each previous capture.
